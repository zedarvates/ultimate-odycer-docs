# Obolune Outcome-Based Services

Status: DECIDED commercial direction / capability implementation varies by service.

## Rule
**Complexity inside. Simplicity outside. Evidence at output.**

Customers buy outcomes, not internal component names. SYSTAI, StoryCore, Botte Secrète, Parcimonia, Knowledge Graphs, models and adapters remain implementation details unless technical inspection is useful.

A commercial label MUST NOT imply a capability is production-proven when its underlying capability is only PROPOSED or EXPERIMENTAL.

## Four primary entry points

### Build My Game
For creating or extending playable game content/systems. SYSTAI interprets intent and proposes the appropriate proven/experimental capability composition according to project policy.

### Build My Story
StoryCore-centered entry point for narrative/game-content work:
- Game Lore Builder
- Story Builder
- Character Builder
- Act Builder
- Scene Builder
- Quest Builder
- Dialogue Builder
- Campaign Builder
- World Story Builder
- Story-to-Game
- Lore & Quest Checker

These are customer-facing outcome names. Each requires a separate capability-status map based on actual StoryCore evidence.

### Optimize My Game
Candidate outcome services include Online Game Optimizer, Game Server Optimizer, Game Performance, Game Asset Optimizer and Game AI Cost/Latency Optimizer. Before/after claims require comparable measured evidence.

### Check My Game
QA/coherence/release-oriented services: game/release checks, lore/quest coherence, compatibility, provenance/licence, security and evidence readiness according to proven capability scope.

## Customer flow
Customer intent -> simple service entry point -> SYSTAI clarification -> project policy/budget -> proposed capability/work graph -> work/evidence -> customer-facing result report.

## Evidence
Optimization/check services should return a Before/After or Findings/Evidence report:
- baseline and measurement context;
- exact changes/findings;
- post-change measurements where comparable;
- unchanged and unknown areas;
- evidence/tests;
- cost/time consumed;
- caveats;
- human-review items.

## Boundaries
GitHub remains canonical for open technical templates/schemas/docs. Obolune presents products/services and links to technical sources where useful. Commercial presentation must not turn Obolune into the registry.
