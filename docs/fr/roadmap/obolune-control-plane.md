# Obolune — Studio de jeux natif IA, éditeur et vitrine

Statut : direction DÉCIDÉE / implémentation progressive.

## Définition
DÉCIDÉ : Obolune est l’identité publique de studio, éditeur, vitrine et plateforme pour des jeux/mondes de styles variés. Il ne se limite pas aux MMORPG et n’est pas le registre technique.

## Frontière ferme
ÉTABLI : les dépôts GitHub restent canoniques pour leur code, modèles et documentation ; UltOd JSON Template Registry reste canonique pour ses modèles et schémas déclaratifs. Obolune peut présenter des vues sélectionnées ou générées et des liens canoniques, mais ne doit pas dupliquer silencieusement l’autorité.

## Expérience publique
Direction DÉCIDÉE : jeux et mondes en premier ; expérience SYSTAI pour les créateurs ; contenu développeur et écosystème ouvert secondaire, relié aux sources canoniques.

## Modèle de studio
Objectif DÉCIDÉ : une très petite équipe humaine amplifiée par un travail structuré assisté par IA, tandis que les humains gardent l’autorité produit, créative et commerciale.
Implémentation EXPÉRIMENTALE : SYSTAI Work Graph, extensions Capability Graph, routage Parcimonia, adaptateurs d’exécution et mécanismes de preuve, jalon et publication.

Botte Secrète mène un travail établi sur l’exécution, la fiabilité et les preuves dans son périmètre démontré ; le routage global des capacités est expérimental. Parcimonia est une direction expérimentale d’optimisation coût/calcul, pas un routage de production établi.

## Produits
Ultimate Odycer, Le Lié et de futurs jeux peuvent être des produits Obolune. Leurs genres et identités restent propres à chaque projet. Les concepts historiques de MMORPG, vie planétaire et science d’Ultimate Odycer ne définissent pas le cœur multi-jeux d’Obolune.

## Surface créateur
Direction DÉCIDÉE : les créateurs peuvent utiliser des flux manuels, locaux, cloud, avec abonnement, collaborateurs ou hybrides. Les contrats d’implémentation exacts restent progressifs/expérimentaux. GitHub reste canonique pour les modèles et schémas ouverts.

## Critère de réussite
Les visiteurs comprennent d’abord les produits/mondes ; les créateurs comprennent les chemins de création disponibles ; les développeurs peuvent atteindre les sources techniques canoniques. L’identité produit, l’identité studio, la plateforme créateur, l’infrastructure et le registre open source restent distincts.
